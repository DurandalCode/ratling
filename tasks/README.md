# Тикеты для исполнителей

Сильная модель (Claude, GPT) работает по `AGENTS.md` напрямую, тикеты ей не нужны. Тикет —
способ отдать **закрытую** правку модели попроще (GLM, Kimi, Grok в opencode / Cursor) так, чтобы
она не ушла в сторону:

```
владелец ──хотелка──▶ планировщик (сильная) ──tasks/NNN-*.md──▶ исполнитель (слабая)
                                                                  │  правит allowed
                                                                  │  python3 tools/verify.py …  ⟲ до PASS
владелец ◀── коммит ── проверяющий (сильная, коротко) ◀──дифф + отчёт──┘
```

- **Планировщик** пишет тикет по [`TEMPLATE.md`](TEMPLATE.md): что именно, в каких числах, какие
  файлы, чем проверить. Задачу на проектирование («придумай, как стабилизировать блок») сначала
  решает сам и режет на закрытые правки.
- **Исполнитель** читает только [`docs/agent-brief.md`](../docs/agent-brief.md) и тикет, гоняет
  `tools/verify.py` до `VERDICT: PASS`, дописывает отчёт в тикет.
- **Проверяющий** запускает `python3 tools/verify.py tasks/NNN-*.md --baseline` (сборка на HEAD и
  разница объёмов), читает дифф против тикета, коммитит или возвращает с замечанием.

Агенты: opencode — `.opencode/agents/{planner,worker,reviewer}.md`; Cursor — правило
`.cursor/rules/tickets.mdc`; Claude Code — скилл `/ticket`.

Имя файла: `NNN-кратко.md`, номер по порядку. Сделанный тикет остаётся в папке как запись
(статус в шапке: `status: done`).
